# 05. 데이터 라이선스

*최종 확인: 2026-08-08*

남의 데이터를 화면에 뿌리는 앱이라면, **수익화의 관문은 코드가 아니라 계약이다.**

## 무료 소스의 함정

무료로 잘 되던 것이 수익이 발생하는 순간 위반이 된다.

| 소스 | 개인 용도 | 상업 용도 |
|---|---|---|
| yfinance (Yahoo) | 연구·교육 목적으로 배포됨. Yahoo API는 개인 용도로 의도됨 | 정식 공급자 라이선스 필요 |
| CoinGecko 무료 티어 | 가능 | 유료 플랜 필요 |

"광고 하나 붙였을 뿐"도 상업 이용이다. 판단 기준은 **매출 발생 여부**지
규모가 아니다.

## 설계 원칙: 공급자를 갈아 끼울 수 있게 만든다

수집기가 특정 공급자에 직접 의존하면, 교체할 때 전부 다시 쓰게 된다.
인터페이스를 하나 두고 그 뒤에 공급자를 숨긴다.

```
수집기 → QuoteProvider(인터페이스) → Yahoo / Polygon / TwelveData / ...
                                       환경변수로 선택
```

여기에 **안전장치를 코드로** 넣는다. 상업 모드에서 개인용 공급자를 고르면
빌드가 실패하게 한다. 사람의 기억에 의존하지 않는 게 요점이다.

```python
if commercial and not provider.commercial_ok:
    raise ProviderLicenseError(...)
```

## 공급자 계약 시 확인할 것

| 항목 | 왜 |
|---|---|
| **재배포(display) 권리** | API 접근권과 별개다. "최종 사용자에게 표시" 조항이 있어야 한다 |
| 커버리지 | 미국만 주는 곳이 많다. 한국·일본·유럽 개별 종목까지 확인 |
| 거래소 수수료 | 거래소별 데이터 요금이 별도로 붙는 경우가 있다 |
| 지연 조건 | 15~20분 지연은 실시간보다 훨씬 싸다. 필요 없으면 사지 않는다 |
| 출처 표기 의무 | 대부분 화면 표기를 요구한다. UI에 자리를 미리 잡아 둔다 |

**필요 없는 실시간을 사지 않는 것이 가장 큰 절감이다.** 하루 두 번 스냅샷이면
되는 앱이 실시간 계약을 하면 요금이 몇 배가 된다.
