# 06. 앱을 여러 개 굴리기

*최종 확인: 2026-08-08*

앱이 하나일 때는 아무 규칙이 없어도 된다. 두 개가 되는 순간 헷갈리는 건
코드가 아니라 **어느 앱의 무엇이었는지**다.

## 원칙: 앱마다 저장소, 대화도 앱마다

- **저장소 1앱 = 1레포.** 한 레포에 두 앱을 넣으면 배포·버전·키스토어가 전부 엉킨다.
- **대화도 앱 단위로 연다.** 한 대화에서 두 앱을 오가면 "아까 그거"가 어느 앱인지
  서로(사람도 AI도) 헷갈린다. 새 앱은 새 대화에서 시작한다.
- **연결은 이 저장소가 한다.** 대화가 끊겨도 [앱 대장](../projects/registry.json)과
  [작업 로그](../worklog/)를 보면 전체가 이어진다.

## 앱 대장 하나만 고친다

`projects/registry.json`에 한 줄 추가하면 끝난다.

```json
{
  "id": "새앱-슬러그",
  "name": "새 앱 이름",
  "repo": "jinhae8971/새앱-슬러그",
  "package": "com.jinhae.새앱",
  "pages": "https://jinhae8971.github.io/새앱-슬러그/",
  "keystore": "새앱-upload.keystore",
  "status": "개발중",
  "started": "2026-09"
}
```

작업 로그가 이 파일에서 추적 대상을 읽는다. 코드에 목록을 박아 두면 앱이 늘 때마다
스크립트를 고쳐야 하고, 결국 **새 앱이 로그에서 조용히 빠진다**.

## 이름 규칙 — 헷갈릴 여지를 없앤다

| 대상 | 규칙 | 예 |
|---|---|---|
| 저장소 | kebab-case, 앱 이름 그대로 | `market-heatmap` |
| 패키지명 | `com.jinhae.<짧은이름>` | `com.jinhae.heatmap` |
| 키스토어 | `<저장소>-upload.keystore` | `market-heatmap-upload.keystore` |
| Pages | `<저장소>` 하위 | `.../market-heatmap/` |
| 태그 | 앱 셸 `v1.1.0`, 콘텐츠 `content-v1.9.0` | |

**패키지명은 한 번 정하면 못 바꾼다.** Play에 올린 뒤 바꾸면 완전히 다른 앱이 되고,
기존 사용자는 업데이트를 못 받는다. 짧고 오래 갈 이름으로 정한다.

## 키스토어는 앱마다 따로, 백업은 한곳에

앱마다 별도 키스토어를 만들되 백업 위치는 한곳으로 모은다.
파일명에 앱 이름이 들어가야 나중에 어느 것인지 안다.

```
Drive/keystores/
  market-heatmap-upload.keystore
  <다음앱>-upload.keystore
```

## 두 번째 앱부터는 복사해서 시작한다

첫 앱에서 만든 것 중 다음은 그대로 재사용된다.

| 재사용 | 파일 |
|---|---|
| PWA 셸 | `manifest.webmanifest`, `sw.js` (네트워크 우선 전략) |
| 안드로이드 셸 | `android/` 전체 — URL과 패키지명만 교체 |
| 빌드 | `build.sh`, `build-aab.sh` |
| 수집 워크플로우 | `.github/workflows/*.yml` |
| 문서 | `CHANGELOG.md` 뼈대, 개인정보처리방침 |

복사한 뒤 **반드시 바꿔야 하는 것**: 패키지명, 앱 이름, WebView URL, 아이콘,
캐시 버전 문자열, 워크플로우 크론 시각(같은 시각에 몰리면 API 한도에 걸린다).

## 흔한 사고

- **키스토어를 다른 앱 것으로 서명** — 서명이 달라 덮어쓰기 설치가 안 된다.
  파일명에 앱 이름을 넣는 이유다.
- **캐시 버전 문자열을 안 바꿈** — 복사한 앱이 원본의 캐시를 건드리진 않지만
  (도메인 경로가 다르므로), 버전을 그대로 두면 다음 배포 때 올릴 곳을 헷갈린다.
- **크론이 겹침** — 여러 앱이 같은 분에 수집하면 데이터 소스 쪽에서 막힌다.
  앱마다 10~15분씩 어긋나게 잡는다.
