# 03. 배포 — 스토어 등록과 테스트 트랙

*최종 확인: 2026-08-08 · 출처: Play Console 고객센터*

## 트랙 구조

| 트랙 | 인원 | 검토 | 용도 |
|---|---|---|---|
| 내부 테스트 | 최대 100명 | 정책·보안 검토를 거치지 않을 수 있음 | 빠른 확인. 업로드 후 보통 몇 초 |
| 비공개 테스트 | 제한 없음 | 첫 릴리스는 수동 검토, 최대 7일 | **프로덕션 액세스 요건에 집계됨** |
| 공개 테스트 | 누구나 | | Play에 테스트 버전 노출 |

**내부 테스트는 12명 요건에 집계되지 않는다.** 지인 배포 목적이면 내부 테스트로
충분하지만, 프로덕션을 목표로 한다면 비공개 테스트에서 시작해야 한다.

## 개인 계정 프로덕션 액세스 요건

2023년 11월 13일 이후 개설한 개인 계정은 이 조건을 채워야 프로덕션에 올릴 수 있다.

- **12명 이상**의 테스터가 비공개 테스트에 **참여 선택(opt-in)** 상태
- **최근 14일 연속** 유지

실무에서 놓치기 쉬운 것들:

- 이메일을 목록에 **추가만 하고 테스터가 참여를 선택하지 않으면 집계되지 않는다.**
- 12명 딱 맞추면 한 명 이탈에 카운트가 깨진다. **15~20명을 목표로 한다.**
- 첫 릴리스 검토에 걸린 일수는 14일에 포함되지 않는다. 시계는 릴리스가 승인되고
  테스터가 실제로 참여한 뒤에 시작된다.
- 테스터는 Google 계정(@gmail.com) 또는 Workspace 계정이 필요하다.

프로덕션 액세스를 한 번 받으면, 이후 업데이트는 14일 테스트를 다시 요구하지 않는다.

## 앱 설정에서 반드시 필요한 것

- 개인정보처리방침 URL — 수집하는 정보가 없어도 **URL 자체는 필수**
- 데이터 보안 설문
- 콘텐츠 등급 설문
- 타겟층
- 스크린샷 휴대전화 최소 2장, 아이콘 512×512, 그래픽 1024×500

금융·의료·정부 관련 설문은 **실제 기능 기준으로 정확히** 답한다. 정보 표시만 하는
앱을 "거래 기능 있음"으로 답하면 불필요한 심사와 서류 요구로 이어진다.

## 통과하지 못하는 대표 사례

- **웹사이트의 웹뷰를 제공하는 것이 주 목적인 앱** — 허가 없이 남의 사이트를
  감싼 앱은 물론이고, 내 사이트라도 앱만의 기능이 없으면 최소기능 정책에 걸린다.
- **이미 Play에 있는 앱과 동일한 경험만 제공하는 앱**
- **모든 사용자 작업 뒤에 전면 광고를 삽입하는 앱**

내 사이트를 감싼 WebView 셸은 사이드로드로는 문제없지만, 스토어 정식 등록을
목표로 한다면 네이티브 기능(오프라인 캐시, 알림, 관심목록 등)이 필요하다.
