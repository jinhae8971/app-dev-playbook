# 마켓 히트맵 — 첫 앱 빌드·배포 전 과정

*2026-08-08 · 웹 대시보드 → PWA → 서명 APK → Play용 AAB까지 하루*

실제로 막혔던 것만 적는다. 각 항목의 마지막 줄은 **다음에 같은 함정을 알아보는 신호**다.

---

## 데이터 수집

### KRX가 데이터센터 IP를 차단한다
- **증상** `data.krx.co.kr`은 200을 주는데 JSON 엔드포인트가 `LOGOUT` + 400.
  네이버 금융은 403.
- **원인** 클라우드 IP 차단. 로컬 PC에서는 되는데 서버에서만 안 된다.
- **해결** KRX Open API(공식) → legacy → 우아한 성능저하 순의 소스 체인.
  하나가 죽어도 파이프라인은 계속 돌고 해상도만 낮아지게.
- **신호** 로컬에서 되는데 CI에서만 실패하면 코드가 아니라 IP를 의심한다.

### KRX Open API 401이 두 종류다
- `Unauthorized Key` → 헤더 이름이나 키 값이 틀림
- `Unauthorized API Call` → **키는 유효한데 그 서비스에 이용신청·승인이 안 됨**
- 인증키 발급과 서비스별 이용신청은 별개 절차다. 승인까지 영업일 하루 정도.
- **신호** 같은 상태코드라도 메시지가 다르면 원인이 다르다. 메시지를 로그에 남긴다.

### ETF AUM 기반 유출입은 소급이 안 된다
- 스냅샷 차분 방식이라 하루 놓치면 그날 데이터는 영구 결측.
- **해결** 실패 시 즉시 알림. 과거 구간은 별도 대용치로 시딩하고 신뢰도를 낮게 매김.
- **신호** "어제 것 다시 받으면 되지"가 안 되는 데이터가 있다. 설계 시점에 구분한다.

## 안드로이드 빌드

### javac가 한글에서 죽는다
- **증상** `unmappable character (0xED) for encoding US-ASCII`
- **원인** 한글 문자열 리소스가 `R.java` **주석**으로 들어가는데 기본 인코딩이 ASCII.
- **해결** `javac -encoding UTF-8`
- **신호** 리소스에 한글이 있으면 무조건 붙인다.

### d8이 람다에서 실패한다
- **증상** `Fatal Error: Unable to find method metafactory`
- **원인** 람다는 desugaring이 필요한데 android.jar 부트클래스패스에
  `java.lang.invoke`가 없다.
- **해결** 익명 클래스로 작성. (Gradle/AGP를 쓰면 desugaring이 자동이라 안 겪는다)
- **신호** 도구를 직접 부르는 빌드에서 최신 문법을 쓰면 이런 게 나온다.

### targetSdk 35는 엣지투엣지가 강제된다
- **증상** 상단 UI가 상태바 아래로 파고들어 가려짐.
- **해결** `setOnApplyWindowInsetsListener`로 시스템바 인셋을 패딩 적용.
  API 30 이상은 `getInsets(Type.systemBars())`, 미만은 `getSystemWindowInset*`.
- **신호** targetSdk를 올리면 빌드 통과 여부와 별개로 실기기에서 한 번 띄워 본다.

### AAB는 APK 빌드와 두 군데가 다르다
1. `aapt2 link --proto-format` (바이너리 아닌 protobuf 리소스)
2. bundletool 디렉터리 구조로 재배치 후 `build-bundle`
- 검증은 `bundletool build-apks --mode=universal`로 설치 가능한 APK를 뽑아본다.

## 프런트엔드

### 웹폰트 로드 전에 잰 텍스트 폭은 틀리다
- **증상** 타일 라벨이 넘치고 겹침. 폭 측정 코드를 넣었는데도 그대로.
- **원인** 측정 시점에 웹폰트가 아직 로드 전이라 **폴백 폰트 기준**으로 쟀다.
  폴백이 더 좁아서 "들어간다"고 판단한 뒤 실제 폰트로 렌더되며 넘침.
- **해결** `document.fonts.ready` 이후 재렌더 + 클립 경로로 물리적 차단.
- **신호** 측정은 확률적 방어, 클립은 확정적 방어. 둘 다 둔다.

### 글자 수로 폰트 크기를 추정하면 안 된다
- 한글은 라틴보다 폭이 넓다. 같은 계수를 쓰면 한글에서만 넘친다.
- `getComputedTextLength()`로 실측하고, 안 들어가면 축약명 → 생략으로 물러난다.

### 티커 폴백이 숫자면 화면에 숫자가 뜬다
- **증상** 좁은 타일에 `373220`, `9983` 같은 숫자가 표시됨.
- **원인** 이름이 안 들어갈 때 티커로 폴백했는데 한국·일본 티커는 숫자다.
  미국·유럽만 보고 테스트해서 못 잡았다.
- **해결** 축약명 필드를 따로 두고, 숫자 티커는 후보에서 제외.
- **신호** 폴백 로직은 **모든 데이터 종류로** 확인한다. 한 시장만 보면 놓친다.

### 서비스워커는 고쳐도 안 바뀐다 — 캐시 버전을 올려도 안 바뀐다
- **증상 1** 캐시 우선 전략이라 기존 사용자는 옛 화면을 계속 본다.
- **1차 해결** 배포마다 캐시 버전 문자열을 올린다.
- **증상 2** 버전을 올렸는데도 여전히 옛 HTML이 나온다. 데이터(JSON)만 최신이라
  "일부만 반영된" 이상한 상태가 된다.
- **원인** install 단계의 `addAll`이 **브라우저 HTTP 캐시**에서 옛 응답을 받아
  새 캐시에 그대로 넣는다. 캐시 버전을 올려도 내용물이 옛것이다.
- **최종 해결** 두 가지를 같이 한다.
  1. install에서 `fetch(new Request(u, {cache:'reload'}))` — HTTP 캐시 우회
  2. **HTML은 아예 네트워크 우선으로** 돌린다 (실패 시에만 캐시)
- **신호** "데이터는 최신인데 화면만 옛것"이면 SW의 HTML 캐시 전략을 의심한다.
  자주 바뀌는 자산을 캐시 우선에 두면 안 된다.

## 버전·기록

### 코드는 커밋되는데 '버전'은 안 올라간다
- **증상** 기능을 여덟 번 배포했는데 APK는 여전히 versionCode 1 / versionName 1.0.
  커밋 61개가 있어도 "지금 쓰는 게 어느 버전인지"를 아무도 모른다.
- **원인** git 히스토리는 *변경 기록*이지 *버전*이 아니다. 웹 셸 구조라 APK를
  다시 배포할 일이 없어서 버전을 올릴 계기 자체가 없었다.
- **해결** 버전 축을 둘로 나눈다.
  · 앱 셸(versionName) — APK가 바뀔 때만. Play 업로드에는 versionCode 필수 증가
  · 콘텐츠(APP_VERSION) — 화면·기능이 바뀔 때. 각 화면 하단에 표시
  화면에 버전을 찍어야 "고쳤는데 안 바뀐다"를 즉시 판별할 수 있다.
- **신호** 웹뷰 셸 앱은 버전이 조용히 멈춘다. 화면에 버전을 노출하지 않으면
  사용자도 개발자도 무엇이 돌고 있는지 모른다.

### 파일마다 API 커밋을 하면 같은 메시지가 쌓인다
- **증상** 커밋 로그에 동일한 메시지가 5~6번 연속. 히스토리가 못 쓰게 된다.
- **원인** Contents API는 파일 하나에 커밋 하나다. 6개 파일을 올리면 커밋 6개.
- **해결** Git Data API로 blob → tree → commit → ref 순서를 직접 만들어
  **여러 파일을 한 커밋으로** 올린다.
- **신호** 배포 로그에 같은 문장이 반복되면 커밋 단위가 잘못된 것이다.

## 보안·운영

### 스크립트 기본값에 비밀번호를 넣지 않는다
- 키스토어 비밀번호를 `${KEYSTORE_PASS:-heatmap2026}` 형태로 기본값을 줬는데,
  저장소가 공개라 그대로 노출됐다.
- **해결** `${KEYSTORE_PASS:?...}`로 바꿔 환경변수 없으면 빌드 실패.
- **신호** 편의를 위한 기본값이 공개 저장소에서는 유출이다.

### 채팅·로그에 토큰을 붙여넣지 않는다
- PAT, 봇 토큰, API 키를 대화에 붙여넣으면 그 자체가 노출이다.
- 작업이 끝나면 폐기·재발급한다. remote URL에 토큰을 박았다면 되돌린다
  (`.git/config`는 평문이다).
